    fix(iCan): drop post-rebase post-connection identity rejection (#47)
    
    * fix(iCan): drop post-rebase post-connection identity rejection
    
    The JugglucoNG 1.0.3 rebase (c100893c7) added a strict post-connection
    identity check (matchesOnboardingIdentity + rejectMismatchedOnboardingCandidate)
    that rejects any iCan BLE candidate whose DIS serial doesn't share an 8/9-char
    prefix with the wizard-supplied 'active code' or onboarding SN.
    
    This breaks the i6 firmware variant that ships a BLE DIS serial
    (e.g. 01OR03MS00070101) with no shared prefix with its 12-char active
    code (e.g. ZA1OR03MSE50). Pre-rebase (April 27 'iCan i6 fix' 87574e093
    was the working baseline), no such rejection existed: any iCan the BLE
    scanner claimed was accepted, and handleResolvedSerial promoted the
    DIS serial into SerialNumber.
    
    Drop the rejection call from the SERIAL_NUMBER characteristic handler
    and remove the rejectMismatchedOnboardingCandidate helper. The
    matchDeviceName filter (iCGM-/Sinocare CGM/ICN- prefix) already keeps
    non-iCan peripherals out, so the blacklist isn't load-bearing for
    single-sensor setups.
    
    ICanHealthConstants.matchesOnboardingIdentity is left in place; it's
    now unused but harmless and might be referenced by future tests.
    
    * fix(iCan): remove dead post-rebase identity-check helpers
    
    Following commit b9fedb42b ('fix(iCan): drop post-rebase post-connection
    identity rejection'), the matchesOnboardingIdentity / onboardingIdentityPrefix
    helpers are no longer called from production code. The rejectedOnboardingAddresses
    blacklist set is also unreachable — only the .clear() call in setOnboardingDeviceSn
    remained, and that was just defensive cleanup for code that no longer adds to it.
    
    Remove the dead helpers, the unreachable blacklist field, the imports that
    became unused, and the now-orphaned tests for the prefix-match rule.
    
    Also inline sanitizeSensorIdentity back into normalizeOnboardingDeviceSn,
    which was its only remaining caller after matchesOnboardingIdentity went away.
